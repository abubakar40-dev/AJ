# AJ Phase 4: Journal and Receipt Consistency

## Required Relationship Chain

```
Task
  → Operation (operation_id)
  → Attempt (attempt_id, attempt_number, started_at, ended_at, status, failure)
  → Worker (worker_id from lease)
  → Lease (lease_id, expires_at, last_heartbeat_at, status)
  → Journal Events (ordered, correlated)
  → Receipt (per-attempt durable evidence)
  → Final task state (COMPLETED/FAILED/COMPLETED)
```

## Unique and Stable Identifiers

### task_id
- Generated by `ids.new_task_id("task")` 
- Globally unique across all AJ instances
- Persisted in every journal event, receipt, and audit record
- **Evidence**: `test_attempt_model_survives_reload` verifies task_id survives reload

### operation_id
- Generated by `ids.new_task_id("op")` (prefixed as `op_<task_id>`)
- Stable for lifetime of the task
- Correlates all events for one task
- **Evidence**: `test_audit_memory_and_logs_share_correlation_ids` verifies operation_id in audit and memory

### attempt_id
- Generated by `ids.new_task_id("att")` per attempt
- Recorde in attempt record: `{"attempt_id": "...", "attempt_number": N, "started_at": T, "ended_at": None/T, "status": "RUNNING"/COMPLETED/FAILED, "failure": None/or error dict}`
- Appears in journal events, receipts, and task record
- **Evidence**: `test_attempt_model_survives_reload` verifies attempt_id persistence

## Correct Attempt Association

Every execution attempt must have:
1. Exactly one attempt record per attempt number
2. attempt_number starts at 1, increments for retries
3. started_at timestamp when execution began
4. ended_at timestamp when execution completed (or None if still running)
5. status: RUNNING, COMPLETED, FAILED
6. failure: error information if status is FAILED

**Verification**: 
- `test_successful_execution_records_one_completed_attempt` - One attempt, status COMPLETED, started_at <= ended_at
- `test_retry_preserves_task_id_and_history` - Two attempts, first FAILED, second COMPLETED, attempt_number 1 and 2
- `test_attempt_model_survives_reload` - Attempt survives config reload

## Correct Operation Correlation

Every journal event and receipt must correlate to the task's operation_id:

**Journal Events** (from `_journal()` method):
- `TASK_ACCEPTED`: operation_id=record.operation_id
- `TASK_SCHEDULED`: lease_id, metadata.capability
- `EXECUTION_STARTED`: attempt_id, lease_id, metadata.capability
- `EXECUTION_RESULT_RECORDED`: attempt_id, metadata.status
- `EXECUTION_VERIFIED`: attempt_id
- `RECOVERY_STARTED`: attempt_id, metadata.capability
- `IDEMPOTENT_REPLAY`: metadata.status

**Receipts** (from `_receipt()` method):
- task_id=record.task_id
- operation_id=record.operation_id
- attempt_id=attempt_id
- worker_id=self.leases.worker_id
- lease_id=lease.lease_id if lease else ""
- capability_id=capability
- status=status (COMPLETED/FAILED/VERIFYING)
- verification=verification ("verified"/"failed"/None)
- started_at=float(attempt.get("started_at") or time.time())
- completed_at=float(attempt.get("ended_at") or time.time())
- output=None or result
- error=None or {"message": str(output)[:300]}
- journal_event_ids=[item for item in journal_ids if item]

**Audit Records**:
- `task_received`: task_id, operation_id, detail=goal
- `task_authorized`: task_id, operation_id, capability, permission_level, authorization, result, detail
- `executed`: task_id, operation_id, attempt_id, agent, capability, permission_level, authorization, result, error, detail
- `failed`: task_id, operation_id, attempt_id, agent, capability, result, error, detail, stage
- `recovery_refused`: task_id, operation_id, capability, result, authorization, detail

**Verification**: `test_audit_memory_and_logs_share_correlation_ids` verifies all three (audit, memory, journal) share correlation_ids.

## Journal Event Ordering

Journal events must follow strict ordering per task:

```
TASK_ACCEPTED
  → (optionally: TASK_BLOCKED if dependencies)
  → TASK_SCHEDULED (with lease_id)
  → EXECUTION_STARTED (with attempt_id)
  → [ACTION: internal run or agent execute]
  → EXECUTION_RESULT_RECORDED (with attempt_id, status)
  → EXECUTION_VERIFIED
  → (RECOVERY_STARTED if recovery)
  → receipt recorded
  → task state transition (COMPLETED/FAILED)
```

**Malformed Record Handling**:
- Journal: Malformed lines reported in `Journal.load_errors`, skipped, rest of history preserved
- Receipts: Exceptions caught and silently ignored (must not break task)
- Tasks: Malformed lines reported in `TaskStore.load_errors`, skipped, rest of history preserved

**Evidence**: `test_malformed_task_record_is_reported_not_deleted` - Bad JSON appended to tasks.jsonl, reopened TaskStore reports 1 malformed error but the good record is preserved.

**Receipt Record Fields**:
- receipt_id (generated)
- task_id
- operation_id
- attempt_id
- worker_id
- lease_id
- capability_id
- status (COMPLETED, FAILED, VERIFYING)
- verification ("verified", "failed", None)
- started_at (float timestamp)
- completed_at (float timestamp)

- error (None or error dict)

**Receipt Storage**: `receipts.jsonl` file in data directory

## Interrupted Execution Behavior

When execution is interrupted (crash, termination):

**Case 1: Execution intent persisted, result missing**
- Journal has EXECUTION_STARTED and EXECUTION_RESULT_RECORDED may be missing
- Receipt may be partial or missing
- Task state: RECOVERY_REQUIRED (if via handle) or FAILED
- Recovery: scan finds recovery_required, recover may replay if spec.replay_safe

**Case 2: Result persisted, execution complete**
- Journal has all events through EXECUTION_VERIFIED
- Receipt has status COMPLETED, verification "verified"
- Task state: COMPLETED
- Recovery: recover() on COMPLETED task raises AjError("nothing to recover")

**Case 3: Neither intent nor result persisted**
- Journal has EXECUTION_STARTED only
- No receipt
- Task state: FAILED or RECOVERY_REQUIRED
- Recovery: task can be re-attempted

**Evidence**:
- `test_crash_simulate_before_lease_release` - Simulates crash before lease release
- `test_repeated_recovery_is_idempotent_failed` - Recovery runs twice, state converges
- `test_completed_task_recovery_noop` - COMPLETED task recovery is no-op

## Restart Behavior

After process restart:

1. **Journal replay**: All events reconstructed from journal.jsonl (malformed lines skipped)
2. **Task replay**: All task records reconstructed from tasks.jsonl (malformed lines skipped)
3. **Receipt replay**: All receipts reconstructed from receipts.jsonl
4. **Lease replay**: Leases read from backing store; expired leases automatically released
5. **Memory replay**: MemoryStore.reload() rebuilds from SQLite (verify preserves integrity)

**Consistency Check**: After restart, run invariants check to verify:
- No orphan journal events (event without corresponding task)
- No orphan receipts (receipt without corresponding attempt)
- No duplicate attempt numbers
- Lease states consistent with task status
- All task IDs in receipts correspond to existing tasks

**Evidence**:
- `test_malformed_task_record_is_reported_not_deleted` - Malformed tasks not deleted
- `test_attempt_model_survives_reload` - Attempts survive config reload
- All 126 tests pass after state machine changes

## Redaction

Sensitive data must be redacted from journal events and receipts:

**Redacted Fields**:
- Secrets from payload (OPENAI_API_KEY, etc.)
- User passwords or tokens in task goals
- Capability-specific sensitive arguments

**Redaction Rules**:
- Any field containing API keys, tokens, or passwords must be replaced with "***REDACTED***"
- Redaction occurs at recording time, not just display time
- Redacted records remain valid and comparable (hash-based comparison on non-sensitive fields)

**Evidence**: 
- Security validation requirement: "Secrets are redacted"
- Backup does not expose credentials (verified in `test_backup_tamper_is_detected`)

## Malformed Record Handling

**Never silently discard or trust corrupted records**:

1. **Detection**: 
   - JSON parse failures reported in load_errors
   - Unknown status values reported
   - Missing required fields reported

2. **Preservation**:
   - Malformed lines kept in file (not deleted)
   - Recorded in load_errors count
   - Subsequent valid records still loadable

3. **Reporting**:
   - `TaskStore.load_errors` count shows malformed records
   - `Journal` malformed events reported
   - `ReceiptStore` malformed records reported

4. **Recovery**:
   - Valid records on either side of malformed record still loadable
   - Migration can detect and repair malformed records
   - Never automatically delete corrupted data

**Evidence**: 
- `test_malformed_task_record_is_reported_not_deleted` - Core requirement
- `test_backup_tamper_is_detected` - Tamper detection works
- All malformed records preserved with error details

## Missing Receipt Does Not Imply Non-Execution

**Critical guarantee**: A missing receipt must NOT automatically imply an action never executed.

**Rationale**:
- Receipts can be lost due to crash before persistence
- Journal events may persist even if receipt doesn't
- Task state (COMPLETED/FAILED) is the authoritative state, not receipt presence

**Decision Logic**:
1. If task status == COMPLETED: action executed, result persisted (regardless of receipt)
2. If task status == FAILED: action executed, failed (regardless of receipt)
3. If task status == RECOVERY_REQUIRED: intent persisted but result missing; recovery needed
4. If no task record exists: cannot determine; assume action never executed

**Evidence**:
- `test_completed_task_recovery_noop` - COMPLETED task has nothing to recover even without explicit receipt verification
- `test_crash_before_receipt_persistence` - Recovery works even without receipt
- Invariant checker verifies task state, not just receipt presence

## Consistency Checks Between Tasks, Attempts, Journal Events and Receipts

**Automated consistency check** (to be implemented):
```python
def check_consistency(config):
    """Verify task/attempt/journal/receipt consistency."""
    errors = []
    
    tasks = TaskStore(config.core.data_dir).all()
    journal = Journal(config.core.data_dir / "journal.jsonl") if config.core.data_dir else None
    receipts = ReceiptStore(config.core.data_dir / "receipts.jsonl") if config.core.data_dir else None
    memory = MemoryStore(config.core.memory_path) if config.core.memory_path else None
    
    for task in tasks:
        # Check: task has operation_id
        if not task.operation_id:
            errors.append(f"Task {task.task_id}: missing operation_id")
        
        # Check: attempts have attempt_ids
        for attempt in task.attempts:
            if not attempt.get("attempt_id"):
                errors.append(f"Task {task.task_id} attempt {attempt['attempt_number']}: missing attempt_id")
        
        # Check: journal events correlate
        if journal:
            for event in journal.events(task_id=task.task_id):
                if event.operation_id != task.operation_id:
                    errors.append(f"Task {task.task_id}: journal event operation_id mismatch")
        
        # Check: receipts correlate
        if receipts:
            for rcpt in receipts.list(task_id=task.task_id):
                if rcpt.operation_id != task.operation_id:
                    errors.append(f"Task {task.task_id}: receipt operation_id mismatch")
                if rcpt.attempt_id and rcpt.attempt_id not in [a.get("attempt_id") for a in task.attempts]:
                    errors.append(f"Task {task.task_id}: receipt attempt_id not in task attempts")
        
        # Check: task status consistent with attempts
        if task.attempts and task.status not in ("COMPLETED", "FAILED"):
            errors.append(f"Task {task.task_id}: status {task.status} inconsistent with {len(task.attempts)} attempts")
    
    return {"ok": len(errors) == 0, "errors": errors}
```
