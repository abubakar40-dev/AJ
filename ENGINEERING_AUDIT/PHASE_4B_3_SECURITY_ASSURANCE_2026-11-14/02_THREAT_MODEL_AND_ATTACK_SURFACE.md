# 02 — Threat Model and Attack Surface

## Scope
Local, read-only AJ↔Hermes integration only: capability `hermes.status.read`, contract `aj.hermes.execution.v0`, fixed command `hermes gateway status` (CLI subprocess, no shell), `local_trust` (non-authenticated), default-disabled, AJ deny-by-default. No new capabilities/commands/remote auth/multi-user guarantees.

## Trust boundaries and execution path
`AJ config/defaults` → `runtime._build_execution` (feature/runtime/capability gates, strict config validation, fail-closed) → `orchestrator.build` (register `hermes.status.read` only when attached+available) → `Aj.handle/_execute` (capability lookup/blockers, AJ authorizer allow/confirm/deny, mandatory audit/lease/journal, HERMES path builds `ExecutionRequest` with correlation args) → `execution.execute(port, request)` (port availability) → `HermesExecutionAdapter.execute` (v0 envelope extraction, `validate_request` contract/allowlist/authz/input/timeout checks, CLI resolve, fixed argv `[resolved,"gateway","status"]`, controlled env allowlist, bounded incremental runner, timeout/kill/reap) → `default_runner` subprocess (no shell) → stdout/stderr bounded collection → redaction/sanitization → honest status/observation/error mapping → `ExecutionResult` + v0 envelope evidence → orchestrator records task evidence/audit/journal/receipt/memory and transitions.

## Attack-surface map (by stage)
| Stage | Inputs | Trust | Controls (verified in source) | Evidence | Key risks |
|---|---|---|---|---|---|
| Config/runtime | config values, feature flags, env overrides | operator/local config | defaults disabled; runtime explicit-enable checks + `strict_config` adapter validation; fail closed to `UnavailableExecutionAdapter` | adapter describe/status, `aj --check` | type coercion/bool-as-int, invalid bounds, permissive legacy path misuse |
| Capability/authorization | capability_id, payload, approval, permission context | AJ-internal after validation | registry/executable/availability checks, `Authorizer`, deny-by-default allowlist (`hermes.status.read`), v0 requires `authorizer=AJ`, `authorization_decision=allow`, `trust_mode=local_trust`, empty input | task/audit/journal/receipt | capability escalation, forged identity claims, request smuggling |
| CLI provenance/argv | `cli_path` config, resolved executable | local filesystem/PATH | reject whitespace/NUL/leading `-`/empty, absolute/which resolution + isfile+executable checks, fixed argv list, `shell=False` | evidence `argv_template`, `cli_resolved` (sanitized) | path substitution/TOCTOU, symlink surprises, arg injection |
| Environment | inherited process env | host process | explicit allowlist copied from `os.environ` only for selected keys | runner receives allowlist dict (tested) | secret leakage/influence via env |
| Process lifecycle | timeout, child behavior, output streams | untrusted child process | bounded incremental readers, timeout with SIGTERM→SIGKILL to pgid+pid, bounded waits/reap, join budgets, finally cleanup | `timed_out/terminated/signal/exit_code` evidence | descendant holding pipes, incomplete cleanup, hangs |
| Output/redaction | stdout/stderr bytes/text | untrusted | decode replace, NUL normalize, incremental caps+truncation, best-effort redaction patterns, no execution of output | bounded sanitized payload/notes | secret leakage, misleading semantic inference |
| Outcome/evidence | runner/adapter results | adapter-mapped | honest status mapping, `hermes_execution_id=null`, exit-0 verified as process outcome only, timeout/failed/rejected never completed | v0 envelope, task evidence/audit/journal/receipt | false success, fabricated IDs, evidence inconsistency |

## Threat model (practical, local read-only)
| ID | Threat | Scenario | Control/evidence | Residual | Severity |
|---|---|---|---|---|---|
| T01 | Capability escalation | request non-`hermes.status.read` or mutate op | allowlist + contract validation + capability registration gating (`validate_request`, adapter reject, registry only when enabled). Tests 4B.1/4B.3 pass | none observed in scope | Medium (mitigated) |
| T02 | Permission/context forgery | claim authenticated/non-local trust or deny/omit authz | v0 requires AJ allow + `local_trust`; `local_trust` documented non-authenticated. Tests pass | caller cannot gain verified identity (by design unavailable) | Medium (mitigated) |
| T03 | CLI arg/shell injection | smuggle args/flags/shell metacharacters | fixed argv array, `shell=False`, input must be empty, cli_path validated; runner receives fixed list. Tests pass | none via request; config cli_path limited to executable path | High (mitigated) |
| T04 | Executable path substitution/provenance | empty/whitespace/relative tricks, `-flag`, dir/non-exec, symlink, TOCTOU | fail-closed invalid/empty/-/whitespace/NUL path, isfile+executable checks, resolved-path evidence; symlink accepted only if resolves executable (safe). Tests pass | TOCTOU between check and exec not fully eliminable; PATH resolution trust | Medium (residual) |
| T05 | Env contamination/secret leakage in | sensitive env influences child | controlled allowlist copy only. Tests pass | allowed vars (PATH/HOME/HERMES_*) still inherited by design | Low |
| T06 | Output secret leakage out | tokens/credentials in stdout/stderr/evidence | best-effort redaction (Bearer/Basic, auth headers, key/value/env, URLs, quoted JSON-like), bounds, untrusted handling. Tests improved/passing | best-effort, not complete guarantee | Medium (residual) |
| T07 | Oversized/continuous output | memory exhaustion/blocking | incremental capped collection + drain-to-EOF, truncation flags. Tests pass | descendant-held pipe can extend reader lifetime (bounded by join budget) | Medium (mitigated) |
| T08 | Timeout/cleanup/process escape | hang, ignore SIGTERM, descendants keep pipes open | timeout + SIGTERM/SIGKILL pgid+pid + bounded waits; returns bounded. Tests pass incl. pipe-holder | best-effort descendant cleanup; cannot prove all descendants killed in every platform case | Medium (residual) |
| T09 | Config coercion/fail-open | bool-as-int, invalid types/bounds, contradictory flags | strict validation when explicitly enabled; runtime fail-closed to unavailable. Tests pass | legacy non-strict construction exists but runtime enabled path uses strict | Medium (mitigated) |
| T10 | False success/fabricated evidence | timeout/reject/failure marked success; invented Hermes ID; semantic health claim | honest status mapping, `hermes_execution_id=null`, exit-0 framed as process outcome only, notes. Tests pass | process exit 0 != semantic health (documented) | High (mitigated) |
| T11 | Evidence persistence inconsistency | partial cross-store writes | existing AJ evidence architecture preserved; no redesign; failures handled by existing semantics. Not fully tested for induced persistence faults in 4B.3 | non-atomic multi-store writes remain (known) | Medium (known residual) |
| T12 | Hermes CLI/version drift | behavior/flags/output change | fixed command/args, read-only preflight historically verified; untrusted output handling | runtime drift not automatically detected | Low/Medium (residual) |

Assumptions: local controlled single-operator environment; filesystem/PATH and installed Hermes CLI trusted to operator context; no remote/multi-user adversary model. Exclusions: remote authn/z, compromised host/OS, kernel exploits, supply-chain compromise of Hermes binary, physical access attacks.
