# 07 — Failure and Recovery Model (preferred future candidate: `hermes.gateway.ensure`, hypothetical)

Model assumes fixed argv, no shell, AJ authorization/audit, bounded subprocess, `local_trust` non-authenticated. Hermes-native operation/state guarantees for `ensure` are **not fully evidenced**; where unknown, AJ must be conservative.

| Scenario | AJ/task state | Evidence expected | Retry decision | User-visible meaning | Manual review? |
|---|---|---|---|---|---|
| 1. Rejected before external execution (policy/contract/config/capability disabled/invalid) | Rejected/Failed-at-authz-or-validation (no spawn) | request/capability/authz decision, rejection reason, no process evidence, `hermes_execution_id=null` | Safe to not retry as same invalid request; fix cause | Operation not executed | No (unless systemic) |
| 2. External process never starts (CLI missing/spawn failure) | Failed, `accepted=false` | spawn error class, no exit/output, timestamps | Retry may be safe after fixing environment (idempotent-intent op) but no auto-retry by default | AJ could not start Hermes command; no evidence of side effect | Usually no, unless prior ambiguity exists |
| 3. Starts and returns success (exit 0) | Completed (process-level) with conservative observation | argv/provenance, exit 0, bounded/redacted output, timing; no semantic guarantee without read-back | Duplicates should be avoided via AJ idempotency key; if effect idempotent, retry low risk but not necessary | Command completed; runtime may be ensured, but AJ cannot prove semantic state without verification evidence | Low; verify via read-only status if needed |
| 4. Starts and returns failure (nonzero/signal) | Failed | exit/signal, stderr/stdout bounded/redacted | Depends on error; ambiguous partial effect possible → cautious/manual before blind retry | Command failed; state may be unchanged or partially changed | **Yes if ambiguity possible** |
| 5. Process times out (AJ terminates local process best-effort) | Timeout, `accepted=true` | timeout flag, partial output, termination/kill signals, bounded wait | **No automatic retry** (effect may have occurred/continued) | Local wait ended; outcome unknown or partial | **Yes** |
| 6. Side effect may have happened but local process timed out / lost visibility | Timeout or Unknown | same as 5 plus explicit uncertainty note; no proof of remote completion | No auto-retry | AJ cannot confirm final external/runtime state | **Yes (required)** |
| 7. External operation ID exists but local evidence persistence fails | Execution occurred; local record incomplete | best-effort: external ID/output in memory if captured before failure, but persistence gap recorded as incident; may be irrecoverable locally | Do not blindly retry | AJ may know an ID/effect occurred but cannot durably prove full chain | **Yes** |
| 8. Local evidence exists but external status unknown | Unknown/requires_manual_review | full local request/process evidence + absence of authoritative external status | No auto-retry; prefer read-only verification probe if safe/available | AJ has local trace but cannot confirm current external state | **Yes** |
| 9. Duplicate request arrives | Deduped to existing task/outcome (if same capability+payload+key) or conflict/reject (if mismatched) | idempotency key lookup/claim evidence | No duplicate execution when safely deduped; conflict requires new decision | Same request recognized / conflicting reuse rejected | Only on conflict or prior unknown |
| 10. Cancellation requested but external cancellation unsupported | `cancel_requested` recorded locally at most; execution may continue/complete/fail/timeout; remote state **unknown** unless Hermes proves cancellation | local cancel request evidence, no proof of remote effect | N/A; do not assume stopped | Cancel requested, but AJ cannot guarantee Hermes/runtime stopped the effect | **Yes if side effect matters** |

**Recovery principles:** never fabricate success/IDs; never equate process death with no side effect; never equate local kill with remote cancellation; prefer read-only verification and manual review over unsafe retry when ambiguity exists.
