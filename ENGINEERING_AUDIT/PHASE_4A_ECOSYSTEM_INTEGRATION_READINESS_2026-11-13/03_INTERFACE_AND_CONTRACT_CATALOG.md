## 5. Integration-relevant gaps requiring new/changed contracts
| Gap | Why current state insufficient | Needed for integration |
|---|---|---|
| AJ↔JARVIS task transport | AJ adapter rejects without agreed endpoint/transport; JARVIS exposes internal Python agent runtime, not a verified network/IPC AJ task API | Versioned request/response contract, authz propagation, correlation/operation IDs, timeout/cancel/idempotency semantics, adapter implementation on both sides |
| AJ↔HELIX canonical target & contract | HELIX path missing; helix copies diverged and Hermes-coupled; no AJ adapter | Identify canonical owner/repo/runtime, define delegation contract and state mapping, avoid duplicate orchestrators |
| AJ↔Hermes execution adapter | Hermes active but AJ has only unavailable port; skill/tool permission and evidence mapping undefined | `ExecutionPort` adapter using verified Hermes interface (CLI/gateway/ACP as chosen), result/evidence translation, timeout/cancel/retry/idempotency, security boundary |
| Cross-component task/result correlation | Multiple ID schemes (AJ task/operation, JARVIS task/orchestration, Hermes session/kanban/run) | Correlation ID standard and mapping table persisted in evidence |
| Authorization/identity propagation | AJ local trust not auth; other components have separate identities/policies | Explicit principal/permission envelope and trusted boundary decision (or fail-closed denial) |
| Memory/evidence ownership boundaries | Personal memory vs task evidence mixed risk across systems | Canonical ownership rules, provenance links, no cross-domain overwrite |
