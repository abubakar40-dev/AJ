## Ownership summary (recommended, evidence-based)
- **AJ should own:** AJ-orchestrated task lifecycle/state, authorization decisions for AJ-controlled operations, operation evidence/audit/recovery semantics, integration coordination contracts/adapters, and honest status/correlation mapping.
- **JARVIS should own:** user-facing personal assistant interaction, personal memory continuity, routine user workflows, and deciding when to delegate — without absorbing AJ control-plane internals.
- **HELIX (once canonical target identified) should own:** complex delegated execution/engineering/research workflows and its own operator UX/identity, receiving work via explicit contract.
- **Hermes should own:** runtime/tool/skill execution environment and its platform/gateway concerns; exposed to AJ only through constrained, evidence-producing adapter boundaries.
- **Cross-cutting rule:** no component becomes the canonical store for another domain's records; integrate via IDs, provenance, and adapters rather than merges.
