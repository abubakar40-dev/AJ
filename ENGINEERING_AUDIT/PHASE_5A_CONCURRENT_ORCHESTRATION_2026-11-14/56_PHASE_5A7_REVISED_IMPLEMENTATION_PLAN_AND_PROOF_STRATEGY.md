## 15. Independent verification protocol (operational)

### 15.1 Independence requirements
- Implementation agent **must not** be the sole verifier of its own changes/claims.
- Verifier must independently inspect: relevant source diffs, test bodies, exact commands, outputs/exit codes, and persisted evidence/side effects.
- Verifier must re-run documented commands from a **clean, documented invocation context** and record working tree state and source revision.
- Verifier must confirm each claimed test reaches the **actual callable and real enforcement boundary** (not helper-only, not mock-core).
- **Limitation:** if a genuinely separate reviewer/session/human is unavailable, record this explicitly and **do not claim independent verification**; criterion status cannot exceed allowed non-independent states per evidence policy.

*A second AI summary of the implementation report is not independent verification.*

### 15.2 Mandatory verifier actions per criterion
1. Identify requirement/test mapping in Doc 54/56 matrix.
2. Review source path(s) and confirm intended enforcement point.
3. Review test body for real-path execution, assertions, and forbidden outcomes.
4. Execute exact documented command(s); capture exit code and full relevant output.
5. Inspect persisted records/artifacts before/after (as applicable) for expected state and absence of forbidden side effects.
6. Tie evidence to exact source revision (`git rev-parse HEAD`) and working-tree status.
7. Record criterion verdict and limitations.

### 15.3 Failure/regression handling
- Record every failure with command, output, and suspected scope.
- No hiding, skipping, weakening, or relabeling failures to obtain green status.
- A criterion with failing/missing/invalid evidence is `FAILED`, `BLOCKED`, or `NOT VERIFIED` as appropriate (never `VERIFIED`).
