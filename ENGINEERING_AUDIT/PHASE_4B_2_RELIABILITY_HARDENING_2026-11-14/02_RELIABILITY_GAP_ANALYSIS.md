# 02 — Reliability Gap Analysis

Evidence-backed gaps in Phase 4B.1 implementation and 4B.2 decisions (no scope expansion; `hermes.status.read` only, fixed `hermes gateway status`, CLI subprocess, default-disabled).

| Area | Current behavior (4B.1, inspected) | Failure risk | Proposed/implemented change | Test evidence |
|---|---|---|---|---|
| Output collection bounds | `default_runner` used `subprocess.run(capture_output=True, text=True)` buffering full stdout/stderr in memory, then truncated strings post-hoc | Unbounded memory/CPU if command emits large/continuous output; bounds not enforced during collection | Replaced with `Popen` + bounded incremental readers (threads drain pipes, cap stored bytes at `stdout_max`/`stderr_max` during collection, continue draining to EOF to avoid writer blocking, mark truncation) | `test_default_runner_bounds_output_during_collection_and_reports_truncation` (real subprocess flood, caps/truncation asserted); existing 4B.1 bounds tests pass |
| Timeout/process lifecycle | `subprocess.run(timeout=...)` relied on library timeout behavior; timeout path attempted limited capture; no explicit process-group cleanup | Hanging/long waits or orphan descendants in edge cases; incomplete cleanup evidence | Enforced timeout via `proc.wait(timeout)`, on timeout send SIGTERM then SIGKILL to process group and pid (POSIX, `start_new_session=True`) and reap with bounded waits; collect partial bounded output already captured; record `timed_out/terminated`; safe finally cleanup | `test_default_runner_timeout_terminates_and_collects_partial` (real subprocess sleep, timed_out true, partial captured, returns <5s); `test_evidence_honesty_no_false_success_no_fabricated_id`; adapter timeout mapping tests pass |
| CLI provenance/argv safety | Resolved executable via `which`/absolute check, rejected whitespace/NUL; fixed argv `gateway status` | Argument-like `cli_path` (e.g. `-bad`) or malformed config could be surprising; limited provenance evidence | Reject empty/whitespace/NUL/leading-`-` cli_path; keep fixed argv template; record sanitized `cli_resolved` and `collection=bounded_incremental` in evidence (non-sensitive) | `test_cli_provenance_rejects_argument_like_and_invalid_path`; `test_rejects_shell_injection_and_arbitrary_cli_path` (4B.1) still passes; fixed argv/env allowlist tests pass |
| Config validation | `_bound_int`/`int(... or default)` in adapter and permissive coercion in runtime; invalid types/negative values often silently defaulted/clamped | Unsafe/misleading config accepted when explicitly enabled; violates fail-closed on invalid config | Added `strict_config` validation in adapter (`_checked_int`, range checks, type checks, default<=max) and stricter runtime validation when explicitly enabled (cli_path/type/bool checks, pass-through to strict adapter); any invalid explicit enablement => fail closed to `UnavailableExecutionAdapter` | `test_strict_config_fail_closed_on_invalid_values`, `test_runtime_fail_closed_on_invalid_hermes_config`; default assembly/enablement wiring tests pass |
| Secret redaction | Single regex for `key[:=]value` forms | Missed common formats (Bearer/Basic tokens, Authorization headers, credential-bearing URLs, env-style secrets) | Expanded best-effort patterns (Bearer, Basic, URL credentials, env-style secret names, key/value/header forms) with preserved labels where useful; documented best-effort (not guarantee) | `test_redaction_patterns_best_effort`; existing redaction/bounds test passes (`sk-secret-token`, `hunter2` removed, `[REDACTED]` present) |
| Output interpretation/classification | Exit 0 => `completed` payload with raw stdout/stderr; timeout/nonzero mapped honestly | Risk of over-interpreting unstructured CLI text as semantic health | Kept raw sanitized output; added conservative `observation` (`exit_zero|nonzero_exit|timeout`) and explicit notes that unstructured output is untrusted and exit/timeout do not prove semantic health; signal termination reported explicitly (`terminated by signal N`), negative exit captured | `test_default_runner_nonzero_and_signal_classification`, `test_malformed_encoding_empty_output_and_unknown_honesty`, `test_evidence_honesty_no_false_success_no_fabricated_id`; live probes completed honestly without invented IDs |
| Evidence/provenance | Basic argv/exit/truncation/timing evidence | Limited diagnostics for lifecycle/truncation source | Added additive evidence: `cli_resolved` (redacted/limited), `signal`, `terminated`, `stdout_truncated`/`stderr_truncated` from collector flags, `collection=bounded_incremental` | Unit/fault/live results include new fields; 4B.1 evidence assertions remain compatible |

## Intentionally not changed (evidence/compatibility)
- No new capabilities/commands, no `--deep/--full`, no JARVIS/HELIX/Hermes source/runtime/config changes, no contract version change, no shell, no automatic retries on ambiguous outcomes, no semantic health inference from stdout text, no fabricated Hermes IDs, no exactly-once/cross-store-atomicity claims.
- Existing `UnavailableExecutionAdapter`/disabled defaults, allowlist, `local_trust` (non-authenticated) semantics, and AJ recovery/evidence subsystems left intact (no redesign). Normalization kept conservative (classification/observation only) because reliable semantic parsing of Hermes CLI status text is not evidenced/stable.
