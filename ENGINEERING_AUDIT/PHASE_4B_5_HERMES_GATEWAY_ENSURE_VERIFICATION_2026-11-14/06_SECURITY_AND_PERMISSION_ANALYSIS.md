# 06 — Security and Permission Analysis

## Verified facts (source observations)
- **CLI boundary and argv shape:** `cmd_gateway_ensure` accepts only `--json` and `--timeout` (argparse). Unknown args rejected by `_GatewayCommandParser` with fixed JSON error and exit 2 (`invalid_invocation`). No user-supplied command payload/target host/port/env passed through CLI to subprocess beyond validated timeout value.
- **No shell execution in ensure/start primitives:** service start uses `subprocess.run` with argv lists; unmanaged start uses `subprocess.Popen([sys.executable, '-m', 'hermes_cli.main', ... 'gateway', 'run', ...], shell not set/default False)`. Control/discovery use local sockets/pipes/files and direct APIs, not shell command strings.
- **Environment handling:** unmanaged spawn builds env from `served_profile_child_env(...)` and explicit assignments (`HERMES_HOME`, `HERMES_GATEWAY_DETACHED`, `PYTHONIOENCODING`), strips many launch/session/supervisor flags (`DAEMON_STRIPPED_ENV` etc.) to avoid inheriting caller policy/pins; carries profile pin/policy as coded. This is controlled construction, not blind inheritance of all caller secrets/flags for daemon lifetime in tested aspects. Service start invokes supervisor tools with fixed argv (inherits process env as normal for subprocess.run unless overridden — not shown overridden).
- **Executable/path handling:** spawned gateway uses `sys.executable` for current interpreter and module invocation (`-m hermes_cli.main`) with repo-root cwd; service discovery/start relies on installed/defined service units/tasks/plists and supervisor binaries resolved by fixed names/paths as implemented. `ensure` itself runs in-process logic then may exec/spawn via those controlled paths.
- **Permissions/identity model:** runtime operates on profile home and local control surfaces; discovery enforces private node/ownership/mode checks for sockets/locks/pointers on POSIX and control validation logic (e.g. uid/peer/ACL/mode constraints in `gateway_runtime_discovery.py`, control socket auth/ticketing elsewhere). Windows/native paths have dedicated handling. **`local_trust` in AJ is not authenticated operator identity**; Hermes-side same-user/local boundary checks exist but are not equivalent to strong authenticated remote identity.
- **Output contract:** `cmd_gateway_ensure` emits machine JSON to stdout (credential-free by design comment) and redirects legacy stdout to stderr during ensure; startup failure report redacts sensitive text (`redact_sensitive_text(..., force=True, redact_url_credentials=True)`) for dead-child tail. `gateway status` and logs are separate surfaces (logs may contain operational/sensitive info depending runtime behavior — general risk).
- **Credential exposure:** ensure CLI payload excludes bootstrap credentials; however starting a real gateway causes it to operate with its configured credentials/env/secrets for platforms/providers as per normal gateway runtime (outside ensure’s JSON boundary).
- **Race conditions:** discovery/start/ownership involve TOCTOU windows inherent to filesystem/service/process state (validated by repeated checks/locks/fences in code), but **not provably race-free** against all adversarial local manipulation or concurrent lifecycle actors.
- **Capability restriction feasibility:** as a subprocess capability, AJ can constrain to fixed argv `['<resolved-hermes>', 'gateway', 'ensure', '--json', '--timeout', '<bounded>']`, no shell, bounded timeout/output parsing, and disabled by default — **feasible in form**, but underlying operation remains mutating/lifecycle-capable and state-dependent.
- **Untrusted caller influence:** if AJ constructs argv strictly (no caller-controlled args except bounded validated timeout within policy), direct argument injection is limited. Environment influence depends on AJ’s subprocess env policy (must be controlled/allowlisted if integrated). Local filesystem/supervisor/profile state can still influence outcomes.

## Runtime observations
- Existing gateway runs under user systemd unit in `~/.hermes` with local socket/state files owned by user (`gateway.sock` 600, lock 600, state 664 etc.). No ensure-induced changes observed.

## Unknowns / risks
- Completeness of secret redaction across all ensure failure paths and all gateway runtime logs/outputs when started.
- Whether all supervisor backends/environments prevent privilege/confused-deputy issues in every deployment; only source-level/local observations available.
- Residual TOCTOU and local-same-user attack surface (malicious local process manipulating profile dir/state) — bounded by OS permissions but relevant on shared/compromised user context.
- A narrowly scoped AJ wrapper does not remove Hermes’ inherent start/replace side-effect authority when conditions trigger it.
